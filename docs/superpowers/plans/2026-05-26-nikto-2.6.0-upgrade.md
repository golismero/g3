# Nikto 2.6.0 Upgrade Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Pin the Nikto plugin to a reproducible 2.6.0 source build, then port Magenta's
multi-format parser into the g3 importer so g3 correctly ingests modern Nikto output.

**Architecture:** Replace `apk add nikto` with a `git clone --branch 2.6.0` source build
(mirroring the testssl plugin). Then rewrite `g3i.py` using Magenta's normalize-then-emit
design (readers → `Finding` → `classify_references` → `build_issues`), adapted to emit the
G3Data issue contract, with three g3-specific fixes already landed in Magenta.

**Tech Stack:** Docker (alpine/python base), Perl (Nikto runtime), Python 3 + lxml
(importer), JSON5 plugin manifest.

**Spec:** `docs/superpowers/specs/2026-05-25-nikto-2.6.0-upgrade-design.md`

## Conventions for this plan (read first)

This plan follows g3's established working agreement, which **overrides the writing-plans
skill defaults**:

- **Tests are user-owned.** Tasks do **not** include "write a failing test" steps. The
  author writes/runs tests. Agent verification is **lint + build only**.
- **Git is user-owned.** Tasks do **not** include `git commit` steps. The user commits at
  the **end of each tier** in one batch. Do not run mutating git commands.
- **No running binaries / live servers.** Verification stops at successful build and lint.
  Runtime smoke-tests (e.g. `docker run … nikto.pl -Version`) are called out as **user**
  actions, not agent steps.
- **Tiered delivery.** Only **Tier 1 is detailed** below. Tiers 2–4 are outlined; each is
  detailed in a follow-up planning pass **after** the previous tier is reviewed with the
  user (per the tiered-plan workflow). Do not start a later tier without that checkpoint.

## Tier 1 — Pin Nikto to 2.6.0 from source

**Outcome:** the plugin image installs Nikto 2.6.0 from git instead of Alpine's package.
CSV wrapper and current importer are untouched; the plugin keeps working as today.

### Task 1.1: Replace `apk add nikto` with a 2.6.0 source build

**Files:**
- Modify: `plugins/attack/nikto/Dockerfile`

**Context:** The current Dockerfile installs Nikto via `apk add nikto` (non-reproducible).
We mirror the testssl plugin's pattern (`plugins/recon/testssl/Dockerfile`): clone the
pinned tag from git, install Nikto's Perl runtime deps (taken from Nikto's own
`Dockerfile`: `perl`, `perl-net-ssleay`, `perl-json`, `perl-io-socket-ssl`,
`perl-xml-writer`, `perl-mime-base64`, `perl-xml-libxml`), and symlink `nikto.pl` onto
`PATH`. Symlinking is safe in 2.6.0 because `nikto.pl` locates its `plugins/`/`databases/`/
`nikto.conf.default` via `FindBin::RealBin` (resolves through the symlink). `git` is added
as a virtual build dep and removed after cloning to keep the image lean. The Python wrapper
layer (lxml, g3p/g3i/g3m, entrypoint) is preserved unchanged.

- [ ] **Step 1: Rewrite the Dockerfile**

Replace the entire contents of `plugins/attack/nikto/Dockerfile` with:

```dockerfile
# We need a Python image for the wrapper scripts (g3p/g3i/g3m).
FROM python:3-alpine

# Pinned Nikto version, overridable for forks/testing.
ARG BUILD_VERSION=2.6.0
ARG NIKTO_URL=https://github.com/sullo/nikto.git

# Install Nikto 2.6.0 from source plus its Perl runtime dependencies.
# git is a build-only dep (virtual), removed after cloning. nikto.pl finds its
# plugins/databases/config via FindBin::RealBin, so the symlink onto PATH works.
RUN apk add --no-cache \
        perl \
        perl-net-ssleay \
        perl-json \
        perl-io-socket-ssl \
        perl-xml-writer \
        perl-mime-base64 \
        perl-xml-libxml \
    && apk add --no-cache --virtual .nikto-build git \
    && git clone --depth 1 --branch "${BUILD_VERSION}" "${NIKTO_URL}" /opt/nikto \
    && rm -rf /opt/nikto/.git \
    && ln -s /opt/nikto/program/nikto.pl /usr/local/bin/nikto.pl \
    && apk del .nikto-build

# Add the Golismero3 Python wrapper.
RUN pip install --no-cache-dir -U lxml
WORKDIR /app/
COPY osvdb2cve.json /app/
COPY --chmod=0755 g3p.sh /usr/bin/g3p
COPY --chmod=0755 g3i.py /usr/bin/g3i
COPY --chmod=0755 g3m.py /usr/bin/g3m
ENTRYPOINT ["/usr/bin/g3p"]
```

- [ ] **Step 2: Lint the Dockerfile**

Run: `hadolint plugins/attack/nikto/Dockerfile`
Expected: no errors. (If `DL3018`/pin-version warnings appear for apk packages, they match
the repo's existing convention — leave as the surrounding plugins do; do not pin Alpine
package versions unless the repo already does.)

- [ ] **Step 3: Build the plugin image**

Run: `make -C plugins/attack/nikto`
Expected: the `osvdb2cve.json` target runs (or is up-to-date), then
`docker build -t ghcr.io/golismero/nikto .` completes successfully — the `git clone` checks
out tag `2.6.0`, all Perl deps install, and the symlink is created. Build success is the
agent's verification boundary.

**User smoke-test (not an agent step):** after the build, the user may confirm the runtime
with `docker run --rm --entrypoint nikto.pl ghcr.io/golismero/nikto -Version` and a quick
scan against a throwaway target, since running binaries is user-owned.

## Tier 2 — Core importer rewrite (CSV path live) — OUTLINE ONLY

Detailed after Tier 1 review. Scope:

- Port `Finding` namedtuple, `classify_references`/`_classify_token`, and `read_csv` from
  `private/magenta/parsers/nikto/nikto.py` into `g3i.py`, **including the three fixes
  already in Magenta**: Unicode-hyphen normalization, URL→taxonomy collapse, and the
  6-field 2.1.5 CSV discriminator.
- Adapt `build_issues` to emit the **G3Data** issue contract (`severity: 2`,
  `affects`, `taxonomy`, `references`, `issues: {host_url: [{path, cve, msg}]}`,
  `_cmd`, `_fp`, `_artifacts`) instead of Magenta's `tools`/`template`/string-severity.
  Preserve the current importer's `_fp` fingerprint form and `_artifacts` handling.
- Keep OSVDB colon-key resolution + hit-rate guard; reuse the committed `osvdb2cve.json`.
- Drop the `_start`/`_end` datetime values (current XML path would crash `json.dump`).
- Live wrapper stays `-Format csv`; plugin fully functional after this tier.
- **Open item for the detail pass:** confirm `_fp`/`_artifacts` semantics against the
  current `g3i.py` and the `.g3p` manifest's `importer.returns`.

## Tier 3 — JSON reader (external/legacy ingestion) — OUTLINE ONLY

- Port `read_json`: 2.6.0 array-of-hosts + 2.5.0 concatenated-fragment repair; loud warning
  + `[]` on unrepairable input. Wire into the format sniffer in `main()`.

## Tier 4 — XML reader (external/legacy ingestion) — OUTLINE ONLY

- Port `read_xml`: hardened lxml parser (XXE/billion-laughs guards), tolerant of doubled
  `niktoscan` and not-well-formed XML, recursive `<item>`, refs from `<references>` child or
  `osvdblink` attr; handle `niktoscan`/`niktoscans`; multi-host.
