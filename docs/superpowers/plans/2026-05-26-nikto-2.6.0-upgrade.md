# Nikto 2.6.0 Upgrade Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Pin the Nikto plugin to a reproducible 2.6.0 source build, then port Magenta's
multi-format parser into the g3 importer so g3 correctly ingests modern Nikto output.

**Architecture:** Replace `apk add nikto` with a `git clone --branch 2.6.0` source build
(mirroring the testssl plugin). Then rewrite `g3i.py` using Magenta's normalize-then-emit
design (readers → `Finding` → `classify_references` → `build_issues`), adapted to emit the
G3Data issue contract, with three g3-specific fixes already landed in Magenta.

**Tech Stack:** Docker (alpine/python base), Perl (Nikto runtime), Python 3 + lxml
(importer), JSON5 plugin manifest.

**Spec:** `docs/superpowers/specs/2026-05-25-nikto-2.6.0-upgrade-design.md`

**Status (2026-05-29):** Tiers 1–3 **shipped and user-verified**. Tier 4 (XML reader)
**deferred** — purely additive, no current need for external-XML ingestion.

## Conventions for this plan (read first)

This plan follows g3's established working agreement, which **overrides the writing-plans
skill defaults**:

- **Tests are user-owned.** Tasks do **not** include "write a failing test" steps. The
  author writes/runs tests. Agent verification is **lint + build only**.
- **Git is user-owned.** Tasks do **not** include `git commit` steps. The user commits at
  the **end of each tier** in one batch. Do not run mutating git commands.
- **No running binaries / live servers.** Verification stops at successful build and lint.
  Runtime smoke-tests (e.g. `docker run … nikto.pl -Version`) are called out as **user**
  actions, not agent steps.
- **Tiered delivery.** Tier 1 was detailed and executed first; Tiers 2 and 3 were detailed
  and executed in successive passes after each previous tier was reviewed with the user.
  Tier 4 is preserved in outline below and deferred.

## Tier 1 — Pin Nikto to 2.6.0 from source — SHIPPED

**Outcome:** the plugin image installs Nikto 2.6.0 from git instead of Alpine's package.

### Task 1.1: Replace `apk add nikto` with a 2.6.0 source build

**Files:**
- Modify: `plugins/attack/nikto/Dockerfile`

**Context:** The current Dockerfile installs Nikto via `apk add nikto` (non-reproducible).
We mirror the testssl plugin's pattern (`plugins/recon/testssl/Dockerfile`): clone the
pinned tag from git, install Nikto's Perl runtime deps (taken from Nikto's own
`Dockerfile`: `perl`, `perl-net-ssleay`, `perl-json`, `perl-io-socket-ssl`,
`perl-xml-writer`, `perl-mime-base64`, `perl-xml-libxml`), and symlink `nikto.pl` onto
`PATH`. Symlinking is safe in 2.6.0 because `nikto.pl` locates its `plugins/`/`databases/`/
`nikto.conf.default` via `FindBin::RealBin` (resolves through the symlink). `git` is added
as a virtual build dep and removed after cloning to keep the image lean. The Python wrapper
layer (lxml, g3p/g3i/g3m, entrypoint) is preserved unchanged.

- [x] **Step 1: Rewrite the Dockerfile**

Replace the entire contents of `plugins/attack/nikto/Dockerfile` with:

```dockerfile
# We need a Python image for the wrapper scripts (g3p/g3i/g3m).
FROM python:3-alpine

# Pinned Nikto version, overridable for forks/testing.
ARG BUILD_VERSION=2.6.0
ARG NIKTO_URL=https://github.com/sullo/nikto.git

# Install Nikto 2.6.0 from source plus its Perl runtime dependencies.
# git is a build-only dep (virtual), removed after cloning. nikto.pl finds its
# plugins/databases/config via FindBin::RealBin, so the symlink onto PATH works.
RUN apk add --no-cache \
        perl \
        perl-net-ssleay \
        perl-json \
        perl-io-socket-ssl \
        perl-xml-writer \
        perl-mime-base64 \
        perl-xml-libxml \
    && apk add --no-cache --virtual .nikto-build git \
    && git clone --depth 1 --branch "${BUILD_VERSION}" "${NIKTO_URL}" /opt/nikto \
    && rm -rf /opt/nikto/.git \
    && ln -s /opt/nikto/program/nikto.pl /usr/local/bin/nikto.pl \
    && apk del .nikto-build

# Add the Golismero3 Python wrapper.
RUN pip install --no-cache-dir -U lxml
WORKDIR /app/
COPY osvdb2cve.json /app/
COPY --chmod=0755 g3p.sh /usr/bin/g3p
COPY --chmod=0755 g3i.py /usr/bin/g3i
COPY --chmod=0755 g3m.py /usr/bin/g3m
ENTRYPOINT ["/usr/bin/g3p"]
```

- [x] **Step 2: Lint the Dockerfile**

`hadolint plugins/attack/nikto/Dockerfile` — clean.

- [x] **Step 3: Build the plugin image**

`make -C plugins/attack/nikto` succeeded — `git clone` checks out tag `2.6.0`, all Perl
deps install, and the symlink is created.

### Tier 1 follow-up — wrapper fixes (emerged during verification)

The first smoke-test surfaced two bugs that traced to Nikto 2.6.0's **tagged-source**
behavior (distinct from HEAD at `2.6.0+48`, which we'd been reading earlier):

1. **2.6.0 treats `-o` as a base name** and unconditionally appends `.<format>`
   (`nikto_core.plugin:1137-1138` at the tag). The wrapper's `-o /artifacts/nikto.csv`
   produced `/artifacts/nikto.csv.csv`; the importer then saw an empty input. (HEAD has an
   "append only if not already present" guard; the tag does not.)
2. **Wrapper failures were swallowed** as silent `DONE`: the `cat … | g3i` pipeline
   returned `g3i`'s exit (0 on empty stdin), `set -e` ignored the mid-pipeline `cat`
   failure, and the trailing unconditional `exit 0` finished the wrapper successfully
   regardless.

`plugins/attack/nikto/g3p.sh` was rewritten to match the sibling-plugin exit-code
convention (nmap / wafw00f / subfinder):

- `-o /artifacts/nikto` (base name) — 2.6.0 writes `/artifacts/nikto.csv`.
- `set -o pipefail`, capture Nikto's `rc` via `|| rc=$?`, end with `exit $rc` — a
  missing-CSV abort or a non-zero Nikto exit reaches the worker as ERROR/WARNING instead
  of silent DONE.
- `tee /artifacts/nikto.txt` for the per-task console-log artifact (parity with siblings).

Two sibling-file additions came along:

- `plugins/attack/nikto/nikto.g3p` tidied: invariants (`-nointeractive`, `-Display V`,
  `-Save /artifacts`) hoisted into the wrapper; only `-host` / `-ssl` remain in the `.g3p`
  commands.
- `plugins/attack/nikto/nikto-slow.g3p` added — same image and fingerprint as `nikto`,
  adds `-Pause 1` for paced scans. Follows the nmap multi-variant pattern (shared image
  and fingerprint → selectable alternatives that dedup against each other). Selectable as
  `nikto-slow`.

## Tier 2 — Core importer rewrite (CSV path live) — SHIPPED

`plugins/attack/nikto/g3i.py` was rewritten per the spec:

- **Ported verbatim from `private/magenta/parsers/nikto/nikto.py`:** `Finding` namedtuple,
  `classify_references` / `_classify_token` / `_url_to_tag` / `_resolve_osvdb` /
  `osvdb_hitrate_warning` / token-pattern regexes / `_TOKEN_OVERRIDES` /
  `_CONCEPT_HARDCODE` / `_KNOWN_JUNK` / `read_csv` / `_host_url` /
  `_strip_csv_injection`. Because these landed in Magenta first, the port brings along
  the three g3-originated fixes (Unicode-hyphen normalization, URL→taxonomy collapse,
  6-field 2.1.5 CSV discriminator).
- **New `build_issues` emits G3Data** instead of Magenta's contract: `severity: 2`,
  `_cmd` (`shlex.join(["nikto.pl"] + sys.argv[1:])` when called from the wrapper), `_fp`
  per-host (default-port stripped via a new `_fp_host` helper, trailing slash — preserves
  the old fingerprint shape), `_artifacts: ["nikto.txt", "nikto.csv"]`, `references`
  includes the Nikto repo URL. No `tools` / `template` fields.
- **OSVDB resolution** uses the colon-keyed map (`OSVDB:<n>`), via `_resolve_osvdb` —
  supersedes the previous dash/colon mismatch latent across the codebase.
- **Tag-less findings dropped** by default (per spec Non-Goals); only `INCLUDE_INFO`
  surfaces them.
- **`osvdb2cve.json` is loaded CWD-relative** (`open("osvdb2cve.json")`) — correct for
  g3's container layout (`g3i` at `/usr/bin`, map COPYed to `/app` which is `WORKDIR`),
  differing from Magenta's `__file__`-relative load.
- **Removed:** the broken OSVDB-based XML parser, the `lxml` / `datetime` imports, and
  the latent `_start = datetime` → `json.dump` crash. XML branch warns + emits `[]`
  (filled in by deferred Tier 4 if ever needed).
- `main()` content-sniffs: Nikto-version banner → `read_csv`; `[`/`{` → Tier 3
  `read_json`; XML → deferred warning + `[]`.

**Fixtures under `samples/`:** `nikto-2.6.0.csv` (real Cloudflare-fronted ground-truth;
all tag-less → `[]`), `nikto-2.6.0-cve.csv` (synthetic CVE-bearing; exercises CVE,
comma-joined multi-CVE, OSVDB, CWE-URL collapse, SSL-row skip, tag-less-drop).

**Verification:** ruff clean; user-tested against `samples/nikto-2.1.5.csv`,
`samples/nikto-2.6.0.csv` (both → `[]`, correct: every finding is tag-less or `OSVDB-0`
informational), and `samples/nikto-2.6.0-cve.csv` (populated report — 4 reported, 1
dropped tag-less, taxonomy matches predicted shape).

## Tier 3 — JSON reader — SHIPPED

Added `_path_from_url` / `_findings_from_json_hosts` / `read_json` to `g3i.py`. `main()`
dispatches the `[`/`{` branch to `read_json`:

- **2.6.0+ array of host objects** → fast `json.loads` path.
- **2.5.0 hand-built concatenated-fragment shape** (`}{` between adjacent host objects,
  no enclosing array) → repair by replacing `}{` with `},{` and wrapping in `[…]`, then
  re-parse.
- Both stages failing → loud `stderr` warning + `[]`. Single-dict input is wrapped to a
  one-element list; non-list/non-dict input warns and returns `[]`.

**Fixtures under `samples/`:** `nikto-2.6.0-cve.json` (populated 2.6.0 array mirroring
the CSV CVE sample — same expected taxonomy), `nikto-2.5.0-fragment.json` (the broken
concatenated shape; exercises the repair path).

**Verification:** ruff clean; user-tested both JSON fixtures. The classifier produces
identical taxonomy from the JSON and CSV CVE samples, confirming the `Finding` namedtuple
seam is doing its job (format-neutral classifier + emit).

## Tier 4 — XML reader — DEFERRED

**Scope preserved for future:** port `read_xml` from
`private/magenta/parsers/nikto/nikto.py` — hardened `lxml` parser (`resolve_entities=False,
no_network=True, load_dtd=False, huge_tree=False` against XXE / billion-laughs), tolerant
of the doubled-`niktoscan` quirk and not-well-formed XML, recursive `<item>` find under
either `niktoscan` or `niktoscans` roots, refs from `<references>` child (2.5.0+) or
`osvdblink` attr (older), multi-host. The `Finding` seam means the existing classifier
and `build_issues` will pick it up unchanged.

**Why deferred:** the live wrapper emits CSV (covered by Tier 2), so XML input only
matters for ingesting external / historical XML reports — not a current need. Tier 4 is
purely additive and has no impact on live scan behavior; it can be picked up later
without disturbing what shipped.
