# g3man CLI — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `g3man`, a new CLI binary that drives the **managed** half of g3api — creating managed scans, populating them with targets/data/imports, dispatching individual tool tasks on demand, polling per-task status, and downloading artifacts. JSON-first, scriptable, debug-tool framing.

**Architecture:** New Go module at `src/g3man/` mirroring `src/g3cli/` in shape (Kong CLI + bearer-token env-var auth + shared `g3lib`). Verbs name *user intent*, not URL paths, so the upcoming HTTP routing migration retrofits one helper function per verb without touching the CLI surface. g3man refuses to operate on non-`MANAGED` scans via a client-side precheck before every per-scan command.

**Tech Stack:** Go (per `src/g3cli/go.mod`: `go 1.26.2`), Kong (`github.com/alecthomas/kong v1.15.0`), kongplete (`v0.4.0`), `g3lib` + `g3log` via `replace` directives. No new third-party dependencies.

**Spec:** `docs/superpowers/specs/2026-05-29-g3man-cli-design.md`

## Tier overview

- **Tier 1 — Skeleton (DETAILED below).** New `src/g3man/` module: `go.mod` with `replace` directives, `g3man.go` with Kong CLI scaffolding (top-level flags `-q/-b/--version`, `completions` subcommand wired through `g3lib.EmitShellCompletion`, env-var loading, ctx-cancel on SIGINT with accurate `"Interrupt received!"` log message), `src/Makefile` wired. Builds and lints clean. The only functional command is `completions`; all other CLI scaffolding (env vars, ctx) is dormant until Tier 2 adds commands that use it.
- **Tier 2 — Read verbs + managed precheck (outline).** Add the `requireManagedScan` client-side helper (one round-trip to `/scan/progress`; will collapse to `GET /scans/{id}` after the REST migration). Implement `ls`, `ps`, `logs`, `get`, `output`, `tools`, `describe`, `env`, `fetch`. `-q` collapses list outputs to newline-separated IDs on `ls`, `ps`, `get`, `output`, `tools`. `fetch` writes the raw artifact bundle to `-o` (default stdout). `ls` filters client-side to `MANAGED` scans; every other per-scan verb pre-checks.
- **Tier 3 — Write verbs (outline).** Implement `new`, `rm` (with `g3lib.AskForConfirmation` + `-f/--force` skip, mirroring g3cli), `target`, `put`, `upload`, `import`, `run`, `cancel`. `-i/--input` reads JSON bodies from stdin/file on `put` and `run` (matches `g3cli scan`'s `-i` pattern). Every write verb runs `requireManagedScan` before its real call (except `new`, which *creates* the managed scan, and `upload`, which is scan-agnostic).
- **Tier 4 — Build / install / CI / docs (outline).** Root `Makefile`: add `g3man` to the `install` symlink list, add `g3man` to `CLI_BINS` for shell-completion installation. `.github/workflows/CI.yml`: release-matrix entry across linux/darwin/windows × amd64/arm64 with `-ldflags "-X main.Version=..."`. `README.md`: short `## g3man` section. `CLAUDE.md`: one-line addition to the binary table.
- **Tier 5 (deferred, optional) — g3cli managed-blind filter.** Modify [src/g3cli/g3cli.go](../../../src/g3cli/g3cli.go) `Ls.Run`, `Ps.Run`, `Logs.Run`, `Export.Run`, `Report.Run` to filter out `MANAGED` scans client-side. After this lands, g3cli and g3man are partitioned by scan status — neither sees the other half. Touches g3cli, not g3man; grouped here for the symmetry. Can also become a follow-up PR.

- [ ] **Step 2: Write `src/g3man/g3man.go`**

Create the file with this exact content. It contains:
- `Version` string (linker-injected on release builds).
- The two required env-var constants.
- The `CmdContext` struct (carries ctx, base URL, token to command Run methods).
- `CompletionsCmd` — the only functional command in Tier 1; pure shell-completion emission, no API call.
- The top-level `CLI` struct with `-q`, `-b`, `--version` flags and the `completions` subcommand registered.
- `main()` with Kong parsing, completion short-circuit, env loading, ctx-cancel wiring, and dispatch.

Tier 2 and Tier 3 add verbs to the `CLI` struct and their associated `Run` methods to this same file. Env loading and ctx-cancel are dormant in Tier 1 (only `completions` runs, and it short-circuits before them), but they need to be in place so Tier 2's first read verb can use them without restructuring `main()`.

```go
package main

import (
	"context"
	"os"
	"os/signal"
	"strings"

	"github.com/alecthomas/kong"
	"github.com/willabides/kongplete"

	"golismero.com/g3lib"
	log "golismero.com/g3log"
)

// Version is overwritten at link time by release builds via
// -ldflags "-X main.Version=...". Stays "dev" for local builds.
var Version = "dev"

const G3_API_BASEURL = "G3_API_BASEURL"
const G3_API_TOKEN = "G3_API_TOKEN"

// CmdContext is passed to every command's Run(vars CmdContext) method.
// Tier 1 populates it but only Tier 2+ commands consume it.
type CmdContext struct {
	Ctx     context.Context
	BaseURL string
	Token   string
}

type CompletionsCmd struct {
	Shell string `arg:"" enum:"bash,zsh,fish" help:"Target shell (bash, zsh, or fish)."`
}

func (c *CompletionsCmd) Run() error {
	return g3lib.EmitShellCompletion(c.Shell, "g3man", os.Stdout)
}

var CLI struct {
	Quiet    bool             `short:"q" default:"false" help:"Quiet mode."`
	Beautify bool             `short:"b" default:"false" help:"Beautify JSON output."`
	Version  kong.VersionFlag `                          help:"Show version and exit."`

	Completions CompletionsCmd `cmd:"" help:"Emit shell completion registration snippet."`
}

func main() {
	// Build the parser (without parsing) so kongplete can hook in for Tab
	// completion before os.Args is consumed.
	parser := kong.Must(&CLI,
		kong.Name("g3man"),
		kong.Description("Golismero3 - Managed-scan CLI (debug/inspection tool for the managed g3api surface)."),
		kong.UsageOnError(),
		kong.ConfigureHelp(kong.HelpOptions{Compact: true}),
		kong.Vars{"version": Version},
	)
	// Short-circuits and exits when the shell invokes us with COMP_LINE set.
	// No-op in normal invocation.
	kongplete.Complete(parser)
	kctx, err := parser.Parse(os.Args[1:])
	parser.FatalIfErrorf(err)

	// `g3man completions <shell>` must work without G3_API_* env vars set
	// — the user is setting up their shell, not making API calls. Short-
	// circuit before the env-var checks below.
	if strings.HasPrefix(kctx.Command(), "completions ") {
		parser.FatalIfErrorf(kctx.Run())
		return
	}

	// Load the environment variables.
	g3lib.LoadDotEnvFile()

	// Initialize the logger.
	log.InitLogger()
	if ll := os.Getenv("G3_CMD_LOG_LEVEL"); ll != "" {
		log.SetLogLevel(ll)
	}

	// Change the log level based on the flags.
	if CLI.Quiet {
		log.SetLogLevel("CRITICAL")
	}

	// Prepare the context variables for the commands.
	var cmdctx CmdContext

	// Get the API base URL.
	cmdctx.BaseURL = os.Getenv(G3_API_BASEURL)
	if cmdctx.BaseURL == "" {
		log.Critical("Missing environment variable: " + G3_API_BASEURL)
		os.Exit(1)
	}

	// Get the shared API bearer token.
	cmdctx.Token = os.Getenv(G3_API_TOKEN)
	if cmdctx.Token == "" {
		log.Critical("Missing environment variable: " + G3_API_TOKEN)
		os.Exit(1)
	}

	// Create the cancellation context for the tool.
	// Inspired by: https://pace.dev/blog/2020/02/17/repond-to-ctrl-c-interrupt-signals-gracefully-with-context-in-golang-by-mat-ryer.html
	ctx := context.Background()
	ctx, cancel := context.WithCancel(ctx)
	cmdctx.Ctx = ctx
	signalChan := make(chan os.Signal, 1)
	signal.Notify(signalChan, os.Interrupt)
	defer func() {
		signal.Stop(signalChan)
		cancel()
	}()
	go func() {
		select {
		case <-signalChan: // first signal, cancel context
			log.Critical("\nInterrupt received!")
			cancel()
		case <-ctx.Done():
		}
		<-signalChan // second signal, hard exit
		os.Exit(1)
	}()

	// Process the command.
	err = kctx.Run(cmdctx)
	parser.FatalIfErrorf(err)
}
```

Notes for the implementer reading this skeleton in isolation:

- The `cmdctx` setup and ctx-cancel goroutine are written now but **only exercised in Tier 2+**. In Tier 1 the only command (`completions`) short-circuits before any of this runs, so static analysis sees reachable code that runtime never actually hits. This is intentional — Tier 2 adds verbs that consume `cmdctx` without restructuring `main()`.
- The `Quiet` / `Beautify` fields are top-level on `CLI`. Tier 1 reads `Quiet` (sets log level); `Beautify` is declared for Tier 2's read verbs to consume. Go doesn't flag unused struct fields, so this lints clean.
- The log message says `"Interrupt received!"` — accurate, since the handler listens for `os.Interrupt` (SIGINT). g3cli's equivalent at [g3cli.go:209](../../../src/g3cli/g3cli.go#L209) mislabels this as `"SIGTERM received!"`; that bug was fixed in g3worker earlier today. g3man is born with the correct label.

## Tier 2 — Read verbs + managed precheck (outline only)

To be detailed after the Tier 1 checkpoint. Anticipated work:

- **`requireManagedScan` helper** in `src/g3man/g3man.go`: small client-side function that calls `/scan/progress` via `g3lib.MakeApiRequest`, finds the scan's row, returns `nil` if `status == STATUS_MANAGED`, returns a descriptive error otherwise. - **`ls`** filters client-side to `MANAGED` scans (everything else stays invisible).
- Verification: per-task build + lint, tier-end full `make bin` + `make lint`. User commits at tier end.
